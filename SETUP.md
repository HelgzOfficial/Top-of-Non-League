# Top of Non League — Setup Guide

This is the real, production-shaped codebase: Next.js 14 + Supabase (Postgres + email-OTP auth) + a
results-ingestion route ready for Vercel Cron. Follow this guide in order — each step unlocks the next.

## What's been verified already, and what hasn't

Being upfront about this so you know where to focus your own testing:

- **Verified for real:** the entire database schema, the "max 2 picks per team" rule (enforced as a
  database trigger, not just UI), and the standings scoring logic were run against a live local
  Postgres instance with seeded data and produced exactly the expected points/goal-difference numbers.
  The 42-gameweek fixture generator was unit-tested and confirmed to produce a mathematically correct
  double round-robin (462 fixtures, 42 games per team, every pair of teams meeting home and away exactly
  once). Every file was parsed for syntax errors and every internal import was checked to resolve to a
  real file.
- **Not verified — needs your machine or Vercel's build:** I built this in a sandboxed environment
  without access to the npm package registry, so I could not run `npm install` or `npm run build` here.
  The code follows well-established Next.js App Router + Supabase SSR patterns, but you (or Vercel,
  automatically, when you deploy) need to run the actual build at least once before trusting it fully.
  The results-ingestion scraper (`src/app/api/ingest-results/route.ts`) was written from a *description*
  of the Football Web Pages fixtures table, not its raw HTML — see step 6 for how to verify and adjust it.

## 1. Create the Supabase project

1. In Supabase, create a new project (any name, e.g. "top-of-non-league").
2. Click the **Connect** button near the top of the project dashboard — it shows your Project URL and
   both API keys together in one place. If you'd rather find them individually: the Project URL is
   under **Integrations → Data API**, and the keys are under **Settings → API Keys**. You need:
   - **Project URL**
   - The publishable/public key — labelled **Publishable key** on newer projects, or **anon public**
     under a "Legacy API Keys" tab on older ones. Either works.
   - The secret key — labelled **Secret key** on newer projects, or **service_role** under Legacy. Keep
     this one private.
3. Copy `.env.example` to `.env.local` and fill in those three values, plus a random string for
   `CRON_SECRET` (e.g. run `openssl rand -hex 32`).

## 2. Run the database migration

1. In the Supabase dashboard, open the **SQL Editor**.
2. Paste the contents of `supabase/migrations/0001_init.sql` and run it. This creates every table, the
   scoring view, the pick-limit trigger, and the Row Level Security policies.
3. (Optional but recommended) If you have the Supabase CLI and a local dev stack, you can instead run
   `supabase/tests/local_verification_seed.sql` against a **local** Supabase project to see the same
   verification I ran — it seeds two fake managers and confirms the standings view computes their
   points and goal difference correctly, then confirms a 3rd pick of the same team is rejected. Do not
   run this against your live hosted project (see the warning at the top of that file).

## 3. Seed the real fixture list

Two ways to do this — pick whichever fits.

**Terminal way:**
```bash
npm install
export $(grep -v '^#' .env.local | xargs)   # loads the three Supabase vars into your shell
node scripts/seed-schedule.mjs
```

**No-terminal way:** open `supabase/seed_fixtures.sql` in a text editor, copy all of it, paste into the
Supabase **SQL Editor**, and click **Run**. Both paths load the same 22 Isthmian Premier Division clubs
(2026/27 season allocation) and all 42 game weeks / 462 fixtures, generated by the verified algorithm in
`generate-schedule.mjs`. Kickoff times are left blank — see step 6 for filling those in from real data,
which is what makes pick deadlines actually lock on time.

Check it worked in Supabase → **Table Editor**: `teams` should have 22 rows, `gameweeks` 42, `fixtures`
462. Re-running either version is safe — it won't create duplicates.

The club list will need updating again next time promotion/relegation happens (roughly once a year, in
summer). `scripts/generate-schedule.mjs` holds the authoritative `TEAMS` list — update it there and
regenerate `seed_fixtures.sql`, or ask me to do it next season.

## 3b. Add club crests

`teams.logo_path` (added by `supabase/migrations/0002_add_team_logos.sql` — run that once, it's a small
additive change safe to run even after you've already seeded fixtures) holds an optional path to each
club's crest image. Teams without one just show a text-initials badge — nothing breaks as you add crests
gradually.

To add a crest:
1. Drop a roughly-square PNG with a transparent background into `public/team-logos/` in the project
   (e.g. `dartford.png`). 256×256 is plenty — no need for anything larger.
2. Add a line to `supabase/update_team_logos.sql` pointing that team at the new file, following the
   existing examples for AFC Whyteleafe and Aveley.
3. Run that file in the Supabase SQL Editor.
4. Redeploy (or just `git push` if auto-deploy is on) so the new image file ships with the app.

One practical note, not legal advice: club crests are typically trademarked by the clubs themselves.
Using them purely to identify teams in a fan app (the way this app does) is common practice among
fantasy-football-style products, but if you plan to grow this commercially it's worth having an
actual conversation with the clubs or the league about it at some point.

## 4. Turn on email OTP sign-in

By default, Supabase's passwordless email sign-in sends a **magic link**, not a 6-digit code. To get
codes instead (which is what this app expects):

1. Go to **Authentication → Email Templates → Magic Link**.
2. Edit the template so it displays `{{ .Token }}` somewhere in the body (Supabase's default template
   already includes this token in the underlying link — you're adding a visible plain-text version of
   it so users can type it in rather than only clicking a link). Save.
3. Go to **Authentication → Providers → Email** and make sure "Enable Email provider" is on. You can
   leave "Confirm email" as-is; OTP sign-in doesn't need it.

## 5. Point Supabase's outgoing email at Brevo

Still in Supabase: click **Authentication** in the left sidebar, then look for **SMTP Settings** (it may
be its own sub-tab, or grouped under a general "Settings" tab within Authentication — Supabase moves
this around between versions). Enable custom SMTP, and fill in:

| Field | Value |
|---|---|
| Sender email | an address on a domain you control (e.g. `noreply@clubosapp.co`) |
| Sender name | Top of Non League |
| Host | `smtp-relay.brevo.com` |
| Port | `587` |
| Username | your Brevo account login email |
| Password | an SMTP key from Brevo → **SMTP & API** settings (not your account password) |

Send yourself a test sign-in from the app once this is set up to confirm the code actually arrives.

## 6. Verify (and fix, if needed) the results scraper

The ingestion route at `src/app/api/ingest-results/route.ts` fetches
`footballwebpages.co.uk/isthmian-football-league-premier-division/fixtures-results` and parses the
fixtures table. I wrote the column layout from a structural description rather than the page's real
HTML, so before relying on it:

1. Deploy the app (step 8) or run it locally with `npm run dev`.
2. Call the route directly with your secret — no terminal needed, just visit this URL in your browser:
   `https://YOUR-DOMAIN/api/ingest-results?secret=YOUR_CRON_SECRET`
   (or, from a terminal: `curl -X POST https://YOUR-DOMAIN/api/ingest-results -H "Authorization: Bearer YOUR_CRON_SECRET"`)
3. Check the JSON response. `resultsWritten` should be greater than 0 once matches have been played,
   and `debug.unmatchedRows` / `debug.writeErrors` should be empty. If team names aren't matching,
   open the page's source in your browser and adjust `COLUMN_INDEX` near the top of the route file to
   match the real column order.
4. Worth knowing before you rely on this: when I checked this source page mid-season for another task,
   it was serving a *different* season's data than the URL implied (stale/cached content on their end,
   not something wrong with this route). Re-check the JSON response after the season actually starts —
   if `resultsWritten` stays 0 with no matched rows even after real matches have been played, that's the
   likely cause, and I can help re-point the scraper at a more reliable source (there's a solid one I
   found and used to verify the fixture list — see supabase/reset_and_reseed_v2.sql's header).
4. Also worth doing: email Football Web Pages about a licensed data feed. A proper API is more reliable
   long-term than scraping, which breaks if they redesign the page.

## 7. Run it locally

```bash
npm install
npm run dev
```

Open `http://localhost:3000` — you should land on the sign-in screen.

## 8. Deploy to Vercel

1. Push this project to a new GitHub repository.
2. In Vercel, "Add New Project" → import that repo.
3. Add the four environment variables from `.env.local` (`NEXT_PUBLIC_SUPABASE_URL`,
   `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `CRON_SECRET`) in Vercel's Project
   Settings → Environment Variables.
4. Deploy. Vercel automatically sends `Authorization: Bearer <CRON_SECRET>` when it triggers a Cron
   Job, which is why the ingestion route checks for exactly that.
5. `vercel.json` schedules the results-checker for once a day at 22:00 UTC — chosen to land after
   same-day Saturday afternoon and midweek evening kick-offs are typically finished. That's the most
   frequent a **Hobby** (free) plan allows; Vercel will refuse to deploy at all if the cron schedule
   asks for more than once a day on Hobby. If you upgrade to **Pro** later, you can tighten this to
   check every 30 minutes on match days by changing the schedule to `*/30 * * * 6,0,2,3`.

## 9. Connect the `topofnonleague.clubosapp.co` subdomain

1. In Vercel, Project Settings → Domains → add `topofnonleague.clubosapp.co`.
2. Vercel will show you a CNAME target (usually `cname.vercel-dns.com`).
3. In your `clubosapp.co` DNS settings, add a CNAME record: host `topofnonleague`, value the target
   Vercel gave you.
4. Wait for DNS to propagate (minutes, occasionally longer) — Vercel issues an SSL certificate
   automatically once it verifies the domain.
